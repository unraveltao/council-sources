# Learning Feedback Loop

> Version: 0.1.0 | Status: Initial operating specification

## Purpose
Adapt teaching and improve the organization using evidence from learning and project work, while preserving knowledge ownership.

## Knowledge domains
- **Organization:** mission, roles, authority, teaching standards, workflows, decisions; Council-owned.
- **Curriculum/Project:** domain maps, syllabus, lessons, exercises, code, experiments, tests; Project/curriculum-owned.
- **Learner:** personal notes, interpretations, progress, questions, reflections; learner-owned.
- **Feedback evidence:** retains its original source and scope; it is not an ownerless memory pool.

## Feedback cycle
1. Observe a concrete learning or engineering outcome.
2. Classify it as learner state, lesson, curriculum, teaching practice, or organizational operation.
3. Verify whether it is repeated evidence or a one-off observation.
4. Recommend the smallest useful change.
5. Apply within delegated authority.
6. Record in the correct owner files with provenance.
7. Evaluate the next learning/engineering outcome.
8. Retain, revise, or revert based on evidence.

## Update classes
- **Learner update:** update learner progress/notes only in the chosen storage location and within granted access.
- **Lesson update:** adjust explanations, examples, practice, or pacing; curriculum owner records the version.
- **Curriculum update:** change sequencing, prerequisites, outcomes, or project milestones when structural evidence supports it.
- **Organizational update:** change recurring standards, role responsibilities, or workflows when a systemic issue is demonstrated.

## Autonomy and approval
The Council may autonomously adapt teaching, improve lesson/curriculum material within agreed goals, improve routine workflows, record verified progress, and apply evidence-backed improvements within scope.

Explicit user approval is required for mission/long-term goal changes, fundamental authority/access/privacy boundaries, major project direction or core language decisions owned by the user, and actions outside authorization.

Internal autonomy does not imply permission to publish publicly.

## Change record
For significant changes record ID/date, affected owner/files, evidence source, fact/inference/proposal/unknown status, previous and new behavior, rationale, impact, authority basis, verification, version, and superseded record.

## Guardrails
Personal notes are not copied into Council memory by default. One misunderstanding does not prove a course is defective. AI-generated work does not prove learner mastery. Do not change policy to compensate for an individual issue unless evidence supports a systemic cause. Preserve history. Record uncertainty when evidence is insufficient.
