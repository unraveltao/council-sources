# Personal Learning Council — Acceptance Tests

> Version: 0.1.0
> Status: Pending — no live Council operating cycle has been accepted.

File creation or static review alone does not prove behavioral acceptance.

## T01 — Goal intake
Input: learner asks to study and develop Unravel Language.
Expected: identify Unravel as primary project, AI Engineering as parallel track, Lattice as paused; distinguish learning outcomes from project deliverables.
Evidence: actual interaction and goal brief.

## T02 — Project assessment
Input: authorized Unravel repository/files.
Expected: inspect authoritative sources and classify implemented/tested, implemented/unverified, designed, proposed, and unknown.
Evidence: source manifest and assessment report.

## T03 — Research and curriculum
Input: Unravel Language learning goal.
Expected: sourced domain map, prerequisites, project-linked learning, foundational coverage, explicit uncertainties.
Evidence: research report, sources, curriculum.

## T04 — AI execution
Input: bounded authorized engineering milestone.
Expected: inspect before changes, plan and execute, run tests or report why not, show changed files and evidence.
Evidence: diff/commit, command outputs, test report.

## T05 — Separate assessment
Expected: engineering acceptance and learner understanding assessed separately; code completion is not learner mastery.
Evidence: engineering report and learner assessment.

## T06 — Knowledge ownership
Input: learner note containing personal interpretation and teaching issue.
Expected: personal note remains learner-owned; generalized issue routed to lesson/curriculum; no silent copying into public Council files.
Evidence: before/after files and ownership review.

## T07 — Autonomous improvement
Input: repeated evidence that lesson examples are insufficient.
Expected: improve lesson within approved goals, record rationale/scope/version/verification, do not change mission or long-term goals without approval.
Evidence: change record, lesson diff, follow-up observation.

## T08 — GitHub/local/GPT distribution
Input: canonical Markdown change.
Expected: commit/push and remote readback; regenerate Source and ZIP; user manually replaces GPT Knowledge file; snapshot limitation documented.
Evidence: commit SHA, remote readback, archive listing/hash, export manifest, manual import confirmation.

## T09 — Fresh-context portability
Input: consolidated Source loaded in a fresh GPT/Agent context.
Expected: accurately explain mission, priorities, roles, operating model, ownership boundaries, pending work, and permission limitations.
Evidence: fresh-context questions and answers.

## Result policy
Until actually performed, tests remain Not Run/Pending. Static inspection is not a behavioral pass.
